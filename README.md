# Έκδοση 0.5 — μέλη και κινητό

- Avatar Admin: φωτογραφίες JPG/PNG/WebP μικραίνουν και κόβονται κεντρικά σε JPEG 192×192. Αποθηκεύονται ιδιωτικά στο voltes_riders.avatar_data_url (έως 90.000 χαρακτήρες), χωρίς δημόσιο bucket. Υπάρχει αλλαγή/αφαίρεση και αρχικά ως εναλλακτική.
- Η σύνδεση Admin παραμένει στη συσκευή μέχρι αποσύνδεση. Το PIN δεν αποθηκεύεται. Το τοπικό τυχαίο διακριτικό ελέγχεται από server με αποθηκευμένο SHA-256. Η αποσύνδεση το διαγράφει από τη βάση. Αλλαγή ADMIN_PIN ή service key ακυρώνει προηγούμενες συνδέσεις. Απαιτείται μία νέα είσοδος μετά την αναβάθμιση.
- Η αρχική δείχνει πέντε τελευταίες διαδρομές. Το κουμπί «Παλαιότερες διαδρομές» ανοίγει ιστορικό με σταδιακή φόρτωση ανά πέντε.
- Το ίδιο κουμπί δήλωσης αλλάζει σε ακύρωση στην ίδια συσκευή/browser. Αποθηκεύεται ξεχωριστό τυχαίο κλειδί ανά βόλτα τοπικά και μόνο το hash του στη βάση. Η ακύρωση δεν γίνεται με όνομα. Διαγραφή δεδομένων browser ή αλλαγή συσκευής χάνει τη δυνατότητα ακύρωσης. Προηγούμενες δηλώσεις χωρίς κλειδί παραμένουν έγκυρες αλλά δεν μπορούν να ακυρωθούν από το νέο κουμπί.
- Σε κινητά, τίτλοι, κάρτες βόλτας και ενέργειες είναι κεντραρισμένα. Φόρμες, ονόματα με avatar και σημειώσεις παραμένουν αριστερά.

Migration: supabase/migrations/202610310002_member_experience.sql. Δημοσίευση με τη σειρά migration → rapid-responder → frontend. Τα υπάρχοντα δεδομένα δεν διαγράφονται.

Έλεγχοι: npm test (29 προηγούμενοι + 23 νέοι), npm run test:db (52 έλεγχοι PostgreSQL σε JSONB και text[]). Χρειάζεται Node.js 22.14+ και npm install για PGlite.

# Ποδηλασία στα Ιωάννινα — 0.4

Ενημέρωση του frontend από το GitHub snapshot 9c65d1d και της Edge Function που δόθηκε στη συνομιλία. Το backend δημοσιεύτηκε στο Supabase στις 31/10/2026 ως rapid-responder v2, μαζί με τη migration ride_completion_v2. Το frontend περιλαμβάνει όλες τις προγραμματισμένες βόλτες και τις 5 πιο πρόσφατες ολοκληρωμένες, χωρίς διαγραφή παλιών δεδομένων.

## Τι προστέθηκε

- Χειροκίνητη υψομετρική ανάβαση (0–50.000 ακέραια μέτρα).
- Χρόνος κίνησης Ω:ΛΛ, χωρίς στάσεις (π.χ. 1:40 → 100 λεπτά). Μέχρι 999:59, χωρίς τεχνητό περιορισμό 24 ωρών.
- Επιβεβαίωση των πραγματικών συμμετεχόντων: οι δηλώσεις συμμετοχής είναι προεπιλογές και μπορούν να αποεπιλεγούν. Τουλάχιστον ένας συμμετέχων απαιτείται.
- Οι επιλογές «δυσκολεύτηκε» αφορούν μόνο πραγματικούς συμμετέχοντες. Προαιρετικό ιδιωτικό σχόλιο Admin έως 2.000 χαρακτήρες.
- Διατηρούνται απόσταση, κοινή μέση ταχύτητα, Strava, PIN, δηλώσεις, μητρώο, μέλη/επισκέπτες, ιστορικό, διαγραφή και PWA, με το ίδιο μαύρο/πράσινο CSS.
- Τα νέα μεγέθη εμφανίζονται στο ιστορικό και αθροίζονται στα στατιστικά των πραγματικών συμμετεχόντων. Παλιά αρχεία με άγνωστα μεγέθη δείχνουν «—».

## Άμεση δοκιμή χωρίς πραγματικά δεδομένα

Με εγκατεστημένο Node.js 22 ή νεότερο, από αυτόν τον φάκελο:

    npm run preview

Άνοιξε http://127.0.0.1:8765. Menu → Είσοδος Admin → δοκιμαστικό PIN **1234**. Ολοκλήρωσε τη δοκιμαστική βόλτα με 35 km, 21 km/h, 120 m, 1:40, τον δοκιμαστικό συμμετέχοντα και ένα σχόλιο. Έλεγξε το ιστορικό, τα στατιστικά και αποσυνδέσου για να διαπιστώσεις ότι τα ιδιωτικά στοιχεία κρύβονται.

Το demo χρησιμοποιεί προσωρινά δεδομένα στη μνήμη, αντικαθιστά το config.js μόνο κατά την εξυπηρέτησή του και δεν συνδέεται στο Supabase. Επανεκκίνηση του server επαναφέρει τη βόλτα. Δεν προσομοιώνει όλες τις λειτουργίες του backend και δεν αντικαθιστά τη δοκιμή σε staging. Τερματισμός με Ctrl+C.

## Δοκιμαστική εγκατάσταση στο Supabase

1. Δημιούργησε δοκιμαστικό αντίγραφο της υπάρχουσας βάσης, μαζί με τους υπάρχοντες πίνακες, περιορισμούς και κατάλληλα δοκιμαστικά δεδομένα. Πάρε αντίγραφο ασφαλείας και κράτησε τον προηγούμενο κώδικα Function/frontend πριν από οποιαδήποτε παραγωγική ενημέρωση.
2. Εφάρμοσε τη migration **supabase/migrations/202610310001_completion_details.sql** στο δοκιμαστικό project. Είναι μία συναλλαγή. Προϋποθέτει τους υφιστάμενους πίνακες voltes_rides, voltes_riders και voltes_signups που χρησιμοποιεί ο παλιός κώδικας. Δεν αποτελεί bootstrap κενής βάσης. Μην την εκτελέσεις ξανά αν έχει ήδη εφαρμοστεί.
3. Διατήρησε το υπάρχον ADMIN_PIN μόνο στα secrets του δοκιμαστικού project. Το SUPABASE_URL και SUPABASE_SERVICE_ROLE_KEY παρέχονται από το Supabase runtime. Κανένα secret δεν μπαίνει στο config.js.
4. Ανάπτυξε τη Function από το **supabase/functions/rapid-responder/index.ts**, μαζί με το **supabase/functions/_shared/completion.js**, με Supabase CLI στο δοκιμαστικό project:

       supabase functions deploy rapid-responder --project-ref YOUR_STAGING_PROJECT_REF

   Το supabase/config.toml διατηρεί το υφιστάμενο συμβόλαιο: ανώνυμες δηλώσεις και server-side PIN για τις ενέργειες Admin. Δεν εισάγει login μέσω Supabase Auth. Το όνομα του endpoint είναι rapid-responder, ανεξάρτητα από την ετικέτα voltes-api στο Dashboard.
5. Σε δοκιμαστικό αντίγραφο του frontend άλλαξε το config.js ώστε να δείχνει στο /functions/v1/rapid-responder του staging. Το παρεχόμενο config.js διατηρεί το υπάρχον URL του project και δεν πρέπει να χρησιμοποιηθεί για δοκιμαστικές εγγραφές στο live.
6. Σέρβιρε τα αρχεία του frontend μέσω localhost ή HTTPS και δοκίμασε την πλήρη ροή: νέα βόλτα, δήλωση από δεύτερο browser, ολοκλήρωση με διαφορετικούς πραγματικούς συμμετέχοντες, ιστορικό, στατιστικά, αποσύνδεση, διαγραφή και ανανέωση δεύτερης συσκευής. Δοκίμασε 0 m, λάθος χρόνο 1:60, καμία συμμετοχή, παρατήρηση για μη συμμετέχοντα και επαναλαμβανόμενη ολοκλήρωση.
7. Έλεγξε από ανώνυμο αίτημα state ότι δεν επιστρέφονται ονόματα, slowed ή slowdownNotes. Ο νέος πίνακας ιδιωτικών σχολίων έχει RLS και πρόσβαση μόνο από service_role. Η migration αφαιρεί επίσης την απευθείας πρόσβαση anon/authenticated στους υπάρχοντες πίνακες: όλες οι λειτουργίες αυτής της εφαρμογής ήδη περνούν από την Edge Function.

Η δημοσίευση στην παραγωγή πρέπει να ακολουθήσει επιτυχή staging δοκιμή: migration → Function → frontend. Το νέο frontend απαιτεί capabilities.rideCompletionV2=true πριν επιτρέψει ολοκλήρωση, ώστε το παλιό backend να μην αγνοήσει σιωπηλά τα νέα πεδία. Οι υπόλοιπες λειτουργίες συνεχίζουν με το παλιό API. Η απευθείας χρήση παλιού frontend για ολοκλήρωση στο νέο backend απορρίπτεται λόγω ελλιπών πεδίων.

## Τεχνικές λεπτομέρειες και επαναφορά

Τα elevation_gain_m και moving_minutes είναι nullable μόνο για παλιές βόλτες. Τα νέα δεδομένα ολοκλήρωσης ελέγχονται στον browser και στον server. Η RPC voltes_finish_ride αποθηκεύει βόλτα, ιδιωτικό σχόλιο και νέους επισκέπτες στην ίδια συναλλαγή. Δεύτερη ολοκλήρωση επιστρέφει 409. Η διαγραφή βόλτας διαγράφει και το ιδιωτικό σχόλιο μέσω foreign key. Τα υφιστάμενα attendees/slowed υποστηρίζονται τόσο ως JSON arrays όσο και ως SQL text arrays. Η κοινή επικύρωση υπάρχει αυτούσια σε δύο αρχεία (frontend και Function), με τεστ ισότητας για να μη διαφέρουν.

Για επαναφορά έκδοσης αποκατάστησε μαζί τον προηγούμενο κώδικα Function και frontend. Κράτησε τις νέες στήλες/πίνακα, ώστε να μη χαθούν καταχωρίσεις. Μην κάνεις DROP για απλή επαναφορά κώδικα. Οι υπάρχουσες πολιτικές RLS δεν διαγράφονται. Η migration εσκεμμένα αποκλείει απευθείας browser πρόσβαση στους πίνακες· άλλοι εξωτερικοί καταναλωτές, αν υπάρχουν, χρειάζονται ξεχωριστό έλεγχο πριν από παραγωγή.
